# Public API requirements

Status: **Draft requirements**. The compiled parser, owned value model, numeric
operations and diagnostics through P040 are implemented and have host unit
evidence. P041 claim status is recorded in [conformance](conformance.md).
The schema engine, validation CLI and editor remain later delivery steps.
Implementation and passing tests do not promote these requirement rows to Verified.

This backlog is adapted from the user-supplied standalone parser proposal dated
2026-10-11. The user's subsequent scope decisions take precedence: a generic
C++17 library for compatible C++ projects, native development without WSL, and
only GoogleTest unit tests and formatting as automated quality checks. The user also requires OS-agnostic embedded usability after compilation into the consuming project, and allows AI agents to change build setup, documentation and unit tests, not production code. See
[scope decision](adr/0001-project-scope.md). AdaptivePi is an optional example,
not a dependency or release authority. The existing Apache-2.0 license is retained.

The functional baseline includes full JSON5 1.0, selectable strict JSON, owned
values, exact numbers, explicit recoverable errors, controlled resource use,
an optional independently buildable Draft-07 validator, CLI and VS Code support.
The parser is developed independently here. A compatible schema/editor component
may be integrated with recorded provenance. A serializer, comment-preserving
formatter, streaming API, C ABI and other schema dialects are outside this baseline.
Source formatting is a development check; it is not a JSON5 formatting product.

The original [proposal Markdown](../core/docs/requirements-proposal-json5-parser-repository.md) is preserved as historical Draft input. These adapted requirements and later user instructions define current scope. Stable J5 IDs preserve proposal traceability; J5-101 records the later embedded requirement. All rows are Draft; issue ownership
and executed unit tests are recorded in [traceability](traceability.md). Planned
checks below are acceptance intentions, not passing evidence. Review a contract
before declaring it implemented; verification requires executed, named unit tests.
The proposal's broader integration/fuzz/sanitizer/benchmark/target/editor-host
acceptance is superseded by the user's unit-test/format scope. Package builds are
development capabilities, not additional integration-test gates.

## Specifications

Language and schema specifications govern syntax and semantics. Project choices
govern C++ ownership, limits, defaults, policies and error reporting.

The specifications govern their respective languages; the requirement rows
define additional library behavior and verification. This file is not a substitute
for reading the referenced grammar while implementing it.

## Draft-07 keyword coverage matrix

This table specifies the coverage obligation in J5-053/057/058/069. Refer to SC/SV
for semantics; do not implement a keyword by its name alone. The meta-schema's
URI and its local copy must be recorded with the release.

| Area | Required coverage |
| --- | --- |
| Core/reference | Boolean and object schemas; `$schema`, `$id`, `$ref`; local/registered references and `definitions`. |
| Types and values | `type` including type arrays and value-based `integer`; `enum`, `const`. |
| Numbers | `multipleOf`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`. |
| Strings | `minLength`, `maxLength`, `pattern`. |
| Arrays | Schema/tuple `items`, `additionalItems`, `minItems`, `maxItems`, `uniqueItems`, `contains`. |
| Objects | `properties`, `patternProperties`, `additionalProperties`, `required`, `propertyNames`, `minProperties`, `maxProperties`, property/schema `dependencies`. |
| Composition/conditions | `allOf`, `anyOf`, `oneOf`, `not`, `if`, `then`, `else`. |
| Metadata | `title`, `description`, `default`, `examples`, `readOnly`, `writeOnly`, `$comment`; retain standard metadata for tooling without mutating instances. |
| Optional assertion vocabulary | `format`, `contentEncoding`, `contentMediaType`: annotation handling required; assertion capability follows J5-069. |

Unknown keywords remain governed by Draft-07 extension rules. Keywords from later
drafts, such as `unevaluatedProperties`, are not silently implemented with a
different dialect's semantics. JSON5 non-finite numbers have no interoperable JSON
Schema value; rejecting them here does not make their syntax invalid to the parser.
Likewise, losslessly parsed unpaired surrogate units may be explicitly outside the
schema component's documented Unicode instance domain and must never be silently
replaced to obtain a passing result.
