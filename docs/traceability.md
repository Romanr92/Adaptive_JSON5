# Requirement traceability

Current ownership follows [the issue tracking section](../core/docs/requirements-json5-implementation-order.md#delivery-scope-and-issue-tracking).
The owner is the final completion anchor for a shared contract; stage-specific
implementation/tests remain in the P groups listed there. All existing named
tests and Draft status are retained. No per-issue report is required; named units
and actual executed evidence must still support any Verified claim.


Every requirement has an owning implementation issue. Issues #2 onward follow
P002–P066; completion issues #68–#72 retain build/runtime/consumer/release work.
The compiled parser and its P001–P040 components, including the P004 cursor,
have implementation and host unit evidence. P038–P041 are tracked by #80;
the P041 review and claim status are in [conformance](conformance.md).
All functional requirement rows remain **Draft**. The named units below record
test existence; executed results and a scoped contract review are separate
evidence and do not automatically establish full requirement verification.

Keep exact `SuiteName.TestName` declarations in the Unit Tests inventory, grouped
by defining file and separated by `; ` when several units cover one requirement. Do not add generated parameter
case suffixes. Record actual execution results in the corresponding step of the [implementation sequence](../core/docs/requirements-json5-implementation-order.md).
The per-production view of the same tests is the
[grammar evidence matrix](../core/docs/design-grammar-evidence.md). Support, limits and deviations
are collected in the [JSON5 1.0.0 support statement](conformance.md).

## Layout and mapping rules

Paths follow [ADR 0002](../core/docs/adr-0002-public-private-source-layout.md)
after the issue #98 restructure: public headers in `includes/adaptive_json5/`,
private headers in `core/includes/`, compiled sources in `core/src/`, internal
units in `core/tests/` and public-interface units in `tests/api`, `tests/memory`
and `tests/value` with shared test providers in `tests/shared_infrastructure`.

- **Source files and functions** lists each production header (and its compiled
  `core/src/` translation unit when one exists) included by the named units,
  with the declared functions and types those units call. It records what the
  tests exercise, not a claim that the requirement is fully implemented.
- **Unit tests** groups the exact `SuiteName.TestName` declarations by the file
  that defines them.
- A requirement with any unit in `core/tests/` is listed under **Core
  requirements**; one evidenced only through public interfaces in top-level
  `tests/` is listed under **API requirements**. Requirements without named
  units are placed by their contract: J5-094–J5-100 quality evidence under core,
  all other public, optional-component and delivery contracts under API. Each
  requirement appears in exactly one section.
