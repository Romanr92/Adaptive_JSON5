# ADR 0005: Allocation-free number reads and linear member lookup

Status: Accepted by the user, 2026-11-10, for issue #124 (review proposal I-01).
Implemented on the #124 branch (production code by Romanr92). Unit evidence is listed
under J5-031, J5-037, J5-050 and J5-051 in [traceability](../traceability.md); executed
results are recorded on the #124 pull request. Requirement status stays Draft.

Open point: the #138 safety analysis (SEooC assumption A-02) asks for one thread per
document and reads without side effects, which is stricter than decision 5. That is
resolved in #138; #124 keeps decision 5.

## Context

Issue #124 reports three defects in reading values from a parsed `json5_document`:

1. `json5_value::as_double()` takes big-integer scratch from the document's own
   storage. A caller-buffer `buffer_arena` only rewinds when nothing is live, which
   never happens while the document lives, so each call consumes buffer space for good
   (the reproduction fails at read 163 on a 4 KiB buffer). `current_bytes()` and
   `peak_bytes()` do not show it.
2. Because a `const` read mutates the document's arena and accounting, two threads
   reading numbers from one document race, although concurrent const reads are
   documented as safe.
3. `json5_value::member()` calls `member_at(position)` in a loop and each call walks
   the sibling list from the start, so one lookup is O(n²).

## Decision

### 1. Conversion runs in four steps; only the last one allocates

`convert_to_floating<T>` (`core/src/value/floating_conversion.cpp`) tries, in order:

1. Special values and certain overflow or underflow (existing).
2. **Clinger fast path**: significand ≤ 2^digits(T) and power of ten ≤ 22 (`double`)
   or ≤ 10 (`float`). One exact multiply or divide is correctly rounded. Disabled when
   `FLT_EVAL_METHOD != 0`.
3. **Eisel–Lemire** (Lemire 2021): decimal significand of at most 19 digits, any
   exponent. Uses a 128-bit power-of-five table and a portable 64×64→128 multiply.
   Returns "unsure" in the rare halfway cases it cannot decide.
4. **Exact big-integer path** (existing): everything else, including more than
   19 significant digits and step-3 "unsure". Uses scratch.

All steps give bit-identical results; steps 2 and 3 only avoid scratch. Rounding
assumes the default IEEE round-to-nearest mode.

### 2. The Eisel–Lemire table is generated by the project

The table is generated by a project-owned generator from its mathematical definition,
not copied from a third-party library, so no new `NOTICE` entry is needed. The
generator and its checked-in output are production artifacts written by the owner.
The data lives in a `.cpp` under `core/src/value/` with a private header under
`core/includes/value/` (ADR 0002). An independent unit recomputes every entry with
exact arithmetic in test code and compares it with the table.

### 3. Build option `ADAPTIVE_JSON5_EISEL_LEMIRE`, default ON

When OFF, the table is not compiled and step 3 is skipped; results are unchanged
and only more inputs use scratch. The option, its default and the table's read-only
size (about 10 KB) are documented in `docs/memory-and-limits.md` and
`docs/embedded.md`. Units cover both settings.

### 4. `buffer_arena` reclaims the most recent block

Releasing the block that ends at the used mark moves the mark back (LIFO). The whole
buffer is still reset when nothing is live. Big-integer scratch is released in
reverse order, so step 4 no longer consumes the caller's buffer.

### 5. Caller-scratch overloads and the thread rule

`json5_value` gains `as_double(const storage_callbacks& scratch)` and, for consistency,
`as_float()` / `as_float(const storage_callbacks& scratch)`. Documented rule in
`json5_value.hpp` and `json5_document.hpp`:

- Navigation and reads are safe from several threads on one `const` document.
- The plain `as_double()` / `as_float()` are safe concurrently for numbers that need
  no scratch: at most 19 significant digits when the option is ON, otherwise the
  Clinger range.
- For any number, pass a per-thread scratch provider to the overload.

The hosted library returns the same `json5_document` and `json5_value`, so it needs no
separate overload.

### 6. `member()` is one linear pass; no lookup work budget

`value_view::find_member(std::string_view)` walks the sibling chain once with the
same integrity checks as `child_at` and still rejects duplicated names.
`json5_value::member()` uses it. A lookup is bounded by `max_members`, so no separate
lookup work budget is added (answers review question 17).

## Consequences

- Ordinary values (`8080`, `1.5`, `6.02214076e23`) are read without allocation and
  without touching shared document state.
- Public API grows by `find_member`, `as_float` and two scratch overloads.
- Embedded users can save about 10 KB of read-only data by turning the option off.
