# Implementation roadmap

The ordered backlog covers all 100 original proposal IDs and the later J5-101
OS-agnostic embedded requirement. Every issue has prerequisites and acceptance
criteria. Contract/API decisions can be discussed before implementation; dependent
behavior is verified only once the necessary production pieces exist.

The current setup includes no production C++. Agents may prepare CMake,
GoogleTest, documentation and requirements; the developer implements the library.
All library errors must use explicit non-throwing outcomes. Automated checks
are GoogleTest unit tests and clang-format only.

A parser-only release is allowed. Schema, CLI and editor prerequisites apply
only to components being shipped; optional consumer examples never block the
generic core. No vendor-specific embedded port or deployment workflow is required.

## Milestones

- [1. Portable foundations](https://github.com/Romanr92/Adaptive_JSON5/milestone/1): Settle draft contracts, portable C++17 targets, Apache-2.0 provenance and unit-test/formatting workflow.
- [2. JSON5 and strict JSON reader](https://github.com/Romanr92/Adaptive_JSON5/milestone/2): Implement complete grammar, owned values, exact numbers and precise recoverable errors.
- [3. Resource and failure contracts](https://github.com/Romanr92/Adaptive_JSON5/milestone/3): Recoverable allocation, explicit limits, bounded work, reusable contexts and deterministic semantics.
- [4. Optional Draft-07 validator](https://github.com/Romanr92/Adaptive_JSON5/milestone/4): Implement an independently buildable offline schema component with exact assertion/reference semantics.
- [5. Host CLI and VS Code](https://github.com/Romanr92/Adaptive_JSON5/milestone/5): Provide usable diagnostics, offline schema assistance and incomplete-document editing through optional host components.
- [6. Optional consumer example](https://github.com/Romanr92/Adaptive_JSON5/milestone/6): Demonstrate externally applied profile/schema policy without coupling the generic library to an application.
- [7. Portable packaging and release](https://github.com/Romanr92/Adaptive_JSON5/milestone/7): Publish reusable CMake targets, supported compiler documentation and truthful unit-test traceability.

The [original proposal](requirements/proposals/json5-parser-repository.md) remains
historical Draft input. [Active requirements](requirements.md) and
[scope ADR](adr/0001-project-scope.md) record later user decisions.

For core parser work, follow the [official-specification implementation sequence](requirements/json5-implementation-order.md).
P001–P041 are ordered so all prerequisites come earlier; existing J5 IDs remain
unchanged for issue and requirement traceability. Optional schema/editor/CLI work
does not block this core parser sequence.
